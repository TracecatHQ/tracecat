Updates and data migrations can be tricky business. We'd love to help on [Discord](https://discord.gg/n3GF4qxFU8).

<Warning>
  If you want to migrate secrets, please make sure to save your database
  encryption / decryption Fernet key. You can find this key in your `.env` file
  assigned to the environment variable: `TRACECAT__DB_ENCRYPTION_KEY`.
</Warning>

## Docker Compose

<Steps>
  <Step title="Download latest environment variables migration script and template">
    Fetch the latest environment variables migration script `env-migration.sh`
    and template `.env.example` to ensure compatibility with the new Tracecat
    version.

    ```
    curl -fL -o env-migration.sh https://github.com/TracecatHQ/tracecat/releases/latest/download/env-migration.sh
    curl -fL -o .env.example https://github.com/TracecatHQ/tracecat/releases/latest/download/env.example
    ```

  </Step>
  <Step title="Execute environment variables migration">
    Run the environment variables migration script to update your existing
    `.env` file with any new or changed variables.

    ```
    chmod +x env-migration.sh && ./env-migration.sh
    ```

    The script keeps only keys that exist in the new template.
    If you set `TRACECAT__IMAGE_TAG` in `.env`, add it back after the migration.

  </Step>
  <Step title="Update Docker Compose Configuration">
    <Warning>
      If you modified `docker-compose.yml` or `Caddyfile`, make copies before
      you continue. The commands below overwrite both files and discard your
      local changes.
    </Warning>

    Download the latest Docker Compose file.

    ```
    # Back up your existing docker-compose.yml first; the download below overwrites it
    cp docker-compose.yml docker-compose.yml.bak
    curl -fL -o docker-compose.yml https://github.com/TracecatHQ/tracecat/releases/latest/download/docker-compose.yml
    ```
  </Step>
  <Step title="Update Caddyfile">
    Download the latest Caddyfile.

    ```
    # Back up your existing Caddyfile first; the download below overwrites it
    cp Caddyfile Caddyfile.bak
    curl -fL -o Caddyfile https://github.com/TracecatHQ/tracecat/releases/latest/download/Caddyfile
    ```
  </Step>
  <Step title="Update the sandbox overlay">
    If you use nsjail, download the latest `docker-compose.sandbox.yml`.

    ```
    # Back up your existing overlay first; the download below overwrites it
    cp docker-compose.sandbox.yml docker-compose.sandbox.yml.bak
    curl -fL -o docker-compose.sandbox.yml https://github.com/TracecatHQ/tracecat/releases/latest/download/docker-compose.sandbox.yml
    ```
  </Step>
  <Step title="Restart Tracecat">
    Pull the new images, then restart Tracecat with the new Docker Compose and `.env` files.

    ```
    docker compose pull
    docker compose up -d
    ```

    With nsjail, run both commands as `TRACECAT__EXECUTOR_BACKEND=nsjail docker compose -f docker-compose.yml -f docker-compose.sandbox.yml …`, the same as the start command. Without the inline variable, Compose reads `TRACECAT__EXECUTOR_BACKEND=direct` from `.env`, which overrides the overlay's `nsjail` default, so the executor runs the `direct` backend inside the privileged overlay.
    To update to a specific version, download the files above from `https://github.com/TracecatHQ/tracecat/releases/download/<version>/<file>` instead, where the env template is `env.example`.
  </Step>
</Steps>

## Update Integrations

Integrations are not automatically updated when you update the Tracecat version.
You will need to manually sync the `tracecat_registry` repository from the **Registry** page:

![Sync registry](/img/custom-actions/sync-from-remote.png)

## Terraform Deployments

All of Tracecat's Cloud deployments are configured using Terraform.
To update Tracecat, update the Terraform variable `tracecat_image_tag` to the latest version and run `terraform apply`.

## Data Migration

Data migrations are non-trivial operations.
We recommend backing up your database before running migrations, especially in a production environment.

<Info>
If the API service fails to spin up due to a data migration error, do not worry.
Your data is still intact. Make sure you backup the core Tracecat database:

- For Docker Compose and AWS EC2 deployments, this would be the `core-db` volume in Tracecat's Docker stack.
- For AWS ECS Fargate deployments, backups are created automatically as part of the RDS postgres service. Just run `terraform apply` with `var.restore_from_backup` set to `true` to restore the latest RDS snapshot.

If you need live migration support, contact us on [Discord](https://discord.gg/n3GF4qxFU8) or email [founders@tracecat.com](mailto:founders@tracecat.com)!
</Info>
