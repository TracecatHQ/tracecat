## Add blocked URL

Action ID: `tools.push_security.add_blocked_url`

Add a URL pattern to URL blocking. Calls POST /v1/controls/blockedUrls. A maximum of 2,000 blocked URLs is supported.

Reference: [https://developer.pushsecurity.com/rest-v1/url-blocking/post-controls-blockedurls](https://developer.pushsecurity.com/rest-v1/url-blocking/post-controls-blockedurls)

### Secrets

Required secrets:

- `push_security`: required values `PUSH_SECURITY_API_KEY`.

### Input fields

<ParamField path="url" type="string" required>

The whole URL pattern - a combination of host and path. The host can be a domain or a subdomain. Wildcards (*) are supported in the path and anywhere in the host, including partial labels and the TLD (e.g. *.com, ai*.domain.com, example.*). Host patterns that match every host, such as * or *.*, are not allowed. If no path is specified, the wildcard * is assumed for path, matching all paths for the derived host.

</ParamField>

</ParamField>

## Add control rule

Action ID: `tools.push_security.add_control_rule`

Add a rule to a browser control. Calls GET then PUT /v1/controls/&#123;control&#125;/configuration. The PUT replaces the whole configuration, so this action reads the current configuration first and sends it back with only this change. Rules are evaluated in order and the first match wins. Edits made to the same control between the read and the write are lost.

Reference: [https://developer.pushsecurity.com/rest-v1](https://developer.pushsecurity.com/rest-v1)

### Secrets

Required secrets:

- `push_security`: required values `PUSH_SECURITY_API_KEY`.

### Input fields

<ParamField path="control" type="string" required>

The control's name in the API path. One of: accountConditionEnforcement, appBanner, appBannerUrlPattern, browserExtensionBlocking, clipboardBlocking, clonedLoginPageDetection, domainCategoryBlocking, fileDownloadBlocking, fileUploadBlocking, mfaEnforcement, maliciousBrowserExtensionDetection, maliciousCopyPasteDetection, passwordLoggingPrevention, phishingToolDetection, strongPasswordEnforcement.

</ParamField>

<ParamField path="rule" type="object" required>

API-native rule without an id. Every control requires name, enabled and mode; mode values, message fields and criteria keys differ by control (see the control's configuration schema). Example for browserExtensionBlocking: &#123;"name": "Block risky extension", "enabled": true, "mode": "BLOCK", "title": "Extension blocked", "subtext": "Contact IT.", "criteria": &#123;"browserExtensions": &#123;"matches": ["&lt;extension id>"]&#125;&#125;&#125;.

</ParamField>

<ParamField path="base_url" type="string | null">

Push Security regional API base URL: https://us1.api.pushsecurity.com (US) or https://eu1.api.pushsecurity.com (EU). Falls back to the workspace variable push_security.base_url.

Default: `null`.

</ParamField>

<ParamField path="position" type="integer | null">

Zero-based index to insert the rule at. 0 makes it the highest-priority rule. null appends it as the lowest-priority rule.

Default: `null`.

</ParamField>
